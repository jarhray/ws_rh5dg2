# 2026-10-13 左手只读诊断与修正

最初启动日志的 `Thumb profile unconfirmed` 是控制门控提示，不表示串口失败。进一步只读查询发现，原驱动将校验正确的异常整组回包标成新鲜数据：角度、温度、错误码等多组数据包含 `-22008/-21846` 和零填充。原始 ROS CDR 数据与 Python 解码一致，排除了 Python 显示问题。

用户确认本体电源接通，并停止独占串口的旧驱动后，独立 Python 工具只发送 `0x11` 读命令，得到：

| 操作 | 结果 |
| --- | --- |
| 1000，读 1 个寄存器 | 手 ID 1 |
| 1136，读 1 个寄存器 | 1648，即原始角度 164.8 度 |
| 1136，读 13 个寄存器 | `1648, -21846, 0, …`，帧头/长度/地址/校验和均正确 |
| 1136–1148，逐个读取 | 13 路可区分的角度值 |
| 1178–1190，逐个读取 | 全部错误码为 0 |
| 1206–1218，逐个读取 | 正常可区分的温度值 |

结论限于实测链路：一次读取多个寄存器的结果不可靠，逐寄存器读取可用。尚未定位差异来自手端固件还是转换器，不能仅因回包校验通过就认定数据有效。

## 已实现的修正

- 增加 `serial_read_mode=single/block`，ROS 节点与单/双手 launch 默认 single。
- single 模式依次读每个地址，13 通道数据或 34 个触觉寄存器全部成功后才提交反馈；任意失败则断连、停用并使反馈失效，不重试。
- 保留 24 位接近值。每组时间戳表示最后一项完成时间，组内通道不属于同时采样。
- 单笔超时默认 40 ms，整组读取上限为 `max(500 ms, 单笔超时)`。
- 拒绝本次观察到的 `0xAAAA` 后接零填充模式。
- 默认角度 5 Hz、力/电流 2 Hz、触觉与慢速项 1 Hz，反馈就绪时新增明确 INFO 日志。

## 验证结果

修改后相关包构建通过；完整离线测试报告 32 项、0 失败，含双手 mock 与 PTY ROS 集成。新增逐寄存器角度/触觉布局及中途超时不返回部分反馈的回归检查。

随后在隔离 ROS 域启动已修正的驱动，显式 `enable_write=false`，对已连接左手只读运行约 10 秒并自动退出：

- `connected=true`、`enabled=false`、`stale=false`，通信错误 0、接受的控制命令 0。
- 13 路错误码均为 0，最终温度为 28–38℃，13 路电流均为 0 mA。
- 观察到 35 个不同角度采集时间戳、18 个力样本、17 个电流样本和 9 个有效触觉消息；这是本次短时观察，不能视为长期频率保证。
- 角度末次样本：`[1648,1650,1652,0,1651,0,1857,1855,1850,1852,1702,1582,2046]`。
- 部分实际角度略超手册标称端点，保留原始值，不据此扩大目标指令限位。
- 电机状态码目前均为 `255`，所给手册未列出该含义；保留原值，不解释为已到位或无故障。力反馈存在小负值，可能涉及零点偏移，但未标定，未擅自归零。

触觉消息已按协议读回；本轮未施加触碰来确认各传感器响应。拇指 profile 仍为 unconfirmed；实测拇指读数不能替代厂商对型号/限位的确认。未执行任何实机目标、速度、力、电流限制、模式、清错或停止写入。

## 重现诊断

先停止驱动，确保串口空闲。以下工具要求独占串口，只实现读请求：

```bash
python3 scripts/probe_serial.py --port /dev/ttyUSB0
python3 scripts/probe_serial.py --port /dev/ttyUSB0 --single-registers
```

正常使用仍通过原 launch 命令即可，默认已改为逐寄存器读取。确认支持整组读取的其它设备可显式指定 `serial_read_mode:=block`。
